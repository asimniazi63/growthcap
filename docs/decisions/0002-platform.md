# 0002: Platform (T2): rulings and known gaps

*2026-10-31. What was built for T2 and the calls made along the way. T3 builds on all of it.*

## Rulings

- **`shopify.app.toml` is written by hand**, not generated by `npm init @shopify/app`. The app is not embedded and has no Shopify extensions, so the generated scaffold would have added nothing. `client_id` comes from the environment; the API version in the file and in `lib/shopify/version.ts` (`2026-10`) must match.
- **Offline access token that doesn't expire.** The OAuth callback stores one encrypted token per shop (AES-256-GCM, key `TOKEN_ENCRYPTION_KEY`, versioned so it can be rotated). The expiring-token option is not used. The refresh columns exist for later and are always empty today.
- **Plain Tailwind, no shadcn/ui yet.** T2 has three small pages. shadcn goes in when T4's chat UI needs it.
- **Tenants are made by `npm run tenant:create` only.** Signing in never creates one, so a new Clerk organization has no access until the command is run for it. The built-in `org:admin` and `org:member` roles give no access; only `gc_admin`, `gc_partner` and `client_viewer` do.
- **One connected shop per tenant, and a shop never changes tenant.** Enforced by two unique indexes and by `connectShop`: a second brand can't take over a shop, even a disconnected one.
- **Webhooks:** HMAC checked on the raw body (timing-safe), duplicates dropped through `webhook_events`, the shop taken from the `X-Shopify-Shop-Domain` header. `app/uninstalled` clears the token and marks the shop disconnected. The three compliance topics are recorded in `compliance_requests`.
- **Vitest timeouts raised to 30 s** (`testTimeout`, `hookTimeout`). The in-memory Postgres tests took 9.5 s and timed out at the default 5 s when the machine was busy.
- **Env objects in the seed scripts are typed `Record<string, string | undefined>`**, because Next's types make `NODE_ENV` required on `ProcessEnv` and the test fixtures don't set it.

## Known gaps (for the README's production section, and for T3)

- **The shop-domain header isn't covered by the webhook HMAC.** Shopify signs the body only. Fine for the demo; a production version should also check the domain inside the payload.
- **Two deliveries of the same webhook at the same instant can both run the handler.** The `webhook_events` check isn't atomic across requests. T3's `orders/create` handler must be an idempotent upsert by order id.
- **`WebhookCtx` carries no database handle.** T3's handlers call `getDb()` themselves, or the context gets a `db`.
- **Seeded orders become unreadable by the product app around 2026-12-30** without `read_all_orders` (see 0001). Resync must never delete rows Shopify stops returning.
- **Solenne's last four orders (O_01021 to O_01024) have the wrong time of day.** The dataset dates them later on 2026-10-31 than the moment of loading, and Shopify stamps a future order time with the load time (about 00:50 New York time instead of 13:33 to 20:04). They are still on 2026-10-31 in the store's time zone, so every per-day figure is unaffected. Only hour-of-day questions would notice. Not worth recreating.
- **`npm run db:migrate` runs by hand**, not from CI or on deploy. Run it after any schema change, before deploying.
